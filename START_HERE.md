# Start Here — SOC Analyst Level 1

Welcome to the **NeoLabs × RIL SOC Level 1 Intern Toolkit**.

This repository has two jobs:

1. **Learn** — NeoLabs-branded SOC/Wazuh learning material, guided synthetic labs and analyst references.
2. **Connect & Operate** — the preconfigured local Wazuh stack plus the NeoLabs pod-authentication client.

Official weekly tasks, evidence and graded submissions belong in the separate **RIL_NeoLabs-Intern-Assignments** repository.

## One-time workstation setup

1. Install the required workstation dependencies listed under `docs/setup/`.
2. Prepare the local `wazuh-stack/` using the approved setup workflow.
3. Do **not** hard-code a pod IP, telemetry URL or pod number into the Wazuh configuration.
4. Obtain the internship lab base URL from NeoLabs/RIL and set it as `NEOLABS_LAB_BASE_URL`.

## Every lab week

You will receive your **pod number** and private **NeoLabs Access Code** through the approved private delivery channel.

From the repository root run:

```bash
python3 tools/neolabs.py login
python3 tools/neolabs.py connect
python3 tools/neolabs.py status
```

You may enter `3`, `03` or `pod-03` when the client asks for your pod number. The server—not your laptop—decides which pod and track the Access Code belongs to.

### What `connect` does for SOC

- refreshes the live server-issued pod manifest;
- uses the existing SOC enrolment control plane to obtain a pod-scoped client certificate when the workstation is not already enrolled;
- updates the local Wazuh enrolment base URL without changing pod scope locally;
- starts the approved local Wazuh stack;
- binds the telemetry collector to **only the pod assigned by the server**.

After that, Wazuh should begin receiving the synthetic telemetry generated by your assigned pod. You do not need to edit the pod IP when VCC is rebuilt.

## Useful commands

```bash
python3 tools/neolabs.py status
python3 tools/neolabs.py pod info
python3 tools/neolabs.py scope
python3 tools/neolabs.py disconnect
```

For SOC, `scope` intentionally does not reveal selectable targets. Pod telemetry authorization remains certificate-bound.

## Learning order

1. Read `LEARNING_PATH.md`.
2. Study the SecOps Foundations material.
3. Complete Wazuh architecture and dashboard tutorials.
4. Use the Query and Command Reference during guided investigations.
5. Practise with the supplied synthetic logs.
6. Use the report/evidence templates when the weekly GitHub Issue requests them.

## Access boundary

SOC interns may use the assigned VCC learner application, approved student-facing dashboard, programme GitHub/Slack/email channels, their local Wazuh environment and the telemetry feed issued for their assigned pod.

SOC interns do not receive direct access to EC2, AWS consoles, production databases, container runtimes, pod hosts, mentor dashboards or production systems.

## Security rules

- Never commit Access Codes, enrolment tokens, certificates, session files or private URLs.
- Never change local files in an attempt to access another pod.
- Never upload raw evidence containing another learner's personal information.
- Use only synthetic datasets and the authorised VCC lab environment.
- Report suspected credential exposure immediately through the approved programme channel.
